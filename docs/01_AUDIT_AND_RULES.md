# 原方案核查、赛事事实与参赛边界

> 版本：1.0｜核查日期：2026-10-26（北京时间）  
> 对象：用户提供的《Total Recall 黑客松开发方案.md》。  
> 本文是开发前审查与规则记录，**不是软件已实现、主网已验证或资格已确认的证明**。本文不授权本轮助手创建账户、部署、公开发布、签名、支付或提交参赛。

## 1. 审查结论

原方案对赛事名称、主要日期、总奖池、评分权重和Memory主网要求的把握基本正确，提供了可保留的“记忆应改变下一次行为”方向。但其“大满贯”策略、若干SDK假设和支付示例不适合直接交给dot照抄。

新版只做 **RecallLedger：面向Sui链上自由职业者的支出纠正助手**。参赛主方向是 **Smart Agents for Real Life**，重点争取 **Best Walrus Memory**。Dot负责独立开发；Tatum AI Builder奖不列入目标；支付协议是P2备选且默认关闭，不进入MVP与比赛主叙事。这是根据评分与实现范围作出的产品决策，不是主办方指定的唯一方向。[赛事主页](https://recall-tatum-walrus.vercel.app/)，访问日期：2026-10-26。

这个选择把可验证的价值集中在一条链路上：

**链上事实核验 → 用途未知时询问 → 用户纠正 → 用户确认适用范围 → Walrus保存规则与例外 → 下次改变分类 → 新客户端恢复 → 同输入有记忆/无记忆对照。**

不把“链上有转账”等同于“知道为什么付款”；不把“召回一段文字”等同于“已找齐有效规则”；不把“能显示一张仪表盘”等同于“有学习效果”。详细产品边界见[PRD与获奖策略](02_PRD_AND_AWARD_STRATEGY.md)。

## 3. 原支付代码存在可直接复核的缺陷

以下是针对附件所给代码的静态审查，不需要以“主网曾被攻击”之类未经验证的事件来支撑。**这些代码不得复制进RecallLedger。**

| 位置 | 实际代码行为 | 后果与处理 |
|---|---|---|
| `hasPaymentAlreadyLanded()` | 只查发送者最近20笔，找任意一笔收款方余额正增加 | 不是针对指定digest的付款证明；分页范围也不覆盖完整付款历史 |
| 支付验证调用 | 读取客户端传入的`txDigest`，但未用它查询/匹配真实交易 | 客户端声明的摘要与被放行的交易没有绑定 |
| 余额匹配 | 只判断`Number(amount) > 0`，没有核对coin type、报价金额、网络与业务订单 | 错币种、错金额、其他业务付款可能被接受；大整数转换还会损失精度 |
| 交易状态 | 未检查成功effects或支付相关的实际转移语义 | “找到交易”不能推出“请求要求的付款已成功” |
| 时间 | 直接相信客户端提交时间，并允许向前偏移一分钟 | 时间窗不能替代服务端生成、绑定、过期和去重的付款意图 |
| `CONSUMED_PAY_IDS` | 进程内`Set`存消费状态 | 重启、多实例、并发请求均无法构成持久、原子的防重放约束 |
| 自定义`x402-sui-direct` | 将自造字段包装成HTTP402并声称标准协议 | HTTP状态码和自定义摘要头本身不足以证明x402/MPP互操作性 |
| 默认收款地址 | 配置缺失时退回硬编码地址 | 配置错误可能伪装成可执行状态；资金路径应拒绝运行，不能用占位地址继续 |

原文还把“记忆账户对象存在”描述为“账户处于激活状态”，但示例只检查返回`data`。对象类型、所有权、当前委托权限、服务可访问性不是同一件事。新方案分别报告这些事实，避免单个绿色状态把未核验条件全部覆盖。

支付P2若未来启用，必须重新验证官方协议适配器、网络、币种、金额、有效期、付款意图、原子持久去重与互操作性，不以本节代码修补后冒充标准实现。协议参考：[x402官方规范仓库](https://github.com/coinbase/x402)、[MPP官方文档](https://mpp.dev/)，访问日期：2026-10-26；精确版本以未来实施当日G0核验为准。

## 4. 原记忆方案的工程缺口

### 4.1 语义召回不能决定当前有效状态

附件用语义召回的前15条结果判断已有记忆、当前规则和是否需要补种。相似度结果并不等于完整事件列表，更不保证最新撤销或例外包含在内。RecallLedger必须证明恢复结果覆盖冻结manifest中的全部预期事件，并核验内容hash后重建状态；语义召回本身不承担完整性保证。当前SDK是否有完整枚举、分页及其数量上限，需要G0实际确认；缺少事件就失败，不在接口受限时悄悄把top-k当全量。本项目只证明受控规模的冻结事件集恢复，不承诺任意大小账户的通用恢复。[协议验收](05_WALRUS_MEMORY_PROTOCOL.md)

### 4.2 “只追加”应作为应用约定

新版使用追加的规则确认、替代、例外、撤销事件，目的在于可追溯和可恢复。不要把某版本SDK没有修改入口推广成所有Walrus数据永久存在、永远不能删除的存储定理。保留期限、删除能力、恢复语义都以实际所用服务和版本为准。不要承诺永久保存或完全无需服务端信任。[Walrus Memory官方入口](https://docs.wal.app/walrus-memory)，访问日期：2026-10-26。

### 4.3 哈希不是自动匿名化

钱包公开地址、交易摘要和可猜测标识的普通哈希可能仍可关联。MVP使用专门的演示身份、公开可引用的链上样本与明确标注的教学样本；不导入用户真实私人财务故事。需要纠正的用途说明先经过用户确认，避免把私密叙述和提示注入一起写入长期记忆。

### 4.4 学习不授予行动权限

本项目只分类、解释和建议，不签名、不转账、不自动购买。过去某类判断正确，只能成为分类规则的证据；不能推导出自动提高花费权限或免审额度。用户确认的规则范围是产品契约，而不是LLM自行升级权限的素材。
